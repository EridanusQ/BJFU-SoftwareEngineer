# 跨服务调用顺序图

## 图编号
SEQ-CROSS

## 模型类型
顺序图

## 建模目的
描述预约链路在 API 网关、预约、会员、支付、通知和监控服务之间的协作与补偿。

## 需求覆盖
FR-006 至 FR-009、FR-014、FR-038、FR-039、NFR-006、NFR-013

## 主要元素
- 参与者：顾客端、API 网关、预约服务、会员服务、支付平台、通知服务、监控/日志。
- 消息覆盖鉴权、权益读取、锁桌、支付、通知补偿和 traceId 写入。
- 异常路径包含锁桌失败、支付超时、通知失败和幂等回调。

## 关键关系
- 预约服务是事务协调者，支付和通知均通过异步回调或补偿完成闭环。
- 监控/日志贯穿请求，支撑 NFR-013 的可观测性。

## 设计取舍
- 将支付回调与通知补偿分离，避免把第三方成功当成系统内部原子操作。
- 明确 traceId 从网关透传到服务和消息，便于 D1-6 追踪验证。

## 评审要点

- 每个关键关系都能在 D1-5 RTM 找到需求 ID、用例 ID、类图实体和测试用例预占 ID。
- 后续如果调整需求编号，应同步修改 PUML、导出图、说明文件与 D1-5 RTM。
