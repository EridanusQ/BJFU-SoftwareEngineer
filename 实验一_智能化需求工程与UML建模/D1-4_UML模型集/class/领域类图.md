# 领域类图

## 图编号
CLS-DOMAIN

## 模型类型
类图

## 建模目的
定义门店、桌位、猫咪、会员、预约、订单、支付、通知、活动和审计等核心领域实体及关系。

## 需求覆盖
FR-001 至 FR-040；NFR-005、NFR-006、NFR-013、NFR-015

## 主要元素
- 实体类超过任务书要求的 12 个，覆盖业务对象、交易对象和支撑对象。
- 关键属性包含状态、时间、金额、授权、traceId 等可测试字段。
- 关系区分聚合、关联和一对多，避免仅列实体名。

## 关键关系
- Store 聚合 TableSlot 与 CatProfile，支撑门店库存和猫咪出勤。
- Reservation 关联 Member、Store、TableSlot、Payment 与 Notification。
- Order 聚合 OrderItem 并关联 Payment，ReviewWorkOrder 来源于 Review。

## 设计取舍
- 类图保持分析模型层级，不加入数据库主外键和具体 ORM 注解。
- TraceLog、AuditLog、ConsentRecord 单独建模，以支撑合规与可观测性需求。

## 导出文件
- SVG：`exports/领域类图.svg`
- PNG：`exports/领域类图.png`

## 评审要点
- 图中的参与者、状态、类名、消息名必须与 D1-3 SRS 和 D1-5 Glossary 保持一致。
- 每个关键关系都能在 D1-5 RTM 找到需求 ID、用例 ID、类图实体和测试用例预占 ID。
- 后续如果调整需求编号，应同步修改 PUML、导出图、说明文件与 D1-5 RTM。
