# D2-4 C4 图集导出清单

本目录保存 C4 图集由 PlantUML 源文件导出的 PNG 与 SVG。PNG 主要用于 Word 文档插图和课程提交预览，SVG 用于矢量查看、局部放大和后续修订检查。架构内容以同名 `.puml` 源文件为准，导出图只作为可视化结果。

## 导出文件说明

- `L1_System_Context.png` / `.svg`：系统上下文图，说明顾客、店员、店长、外部支付平台、短信/通知服务、监管合规和外部 AI 推荐能力等系统边界。
- `L2_Container.png` / `.svg`：容器图，说明 Web 前端、预约服务、会员服务、支付适配器、通知服务、运营后台、预约数据库、会员数据库和日志监控之间的协作关系。
- `L3_Component_Reservation.png` / `.svg`：预约服务组件图，说明可用性查询、预约创建、容量锁、支付协作、状态机和事件发布等核心组件。
- `L3_Component_Member.png` / `.svg`：会员服务组件图，说明会员资料、积分、优惠券、隐私授权和账户状态等组件职责。
- `L4_Code_ReservationCore.png` / `.svg`：预约核心代码协作图，说明 `Reservation` 聚合、`CapacityLock`、`Deposit`、策略对象和领域事件之间的关系。

## 维护要求

1. 图中文字必须与 D2-2 的限界上下文名称一致，避免同一服务在不同产物里出现多个叫法。
2. L2 容器图中的每个服务，都应能在 D2-5 OpenAPI 契约或 D2-6 数据字典中找到对应说明。
3. L3/L4 图中的核心对象应能支撑 D2-1 Top-10 QAS 中的关键质量场景，例如容量锁、幂等、支付失败补偿和 traceId 追踪。
4. 若图中服务边界、接口方向或数据库归属发生变化，应先修改 `.puml`，再重新导出 PNG/SVG，最后同步更新 README、ADR 和 Word 正文。
5. 提交前需检查 PNG 未被拉伸、裁切或压缩到无法阅读；SVG 应保留用于查看细节和后续二次修改。
